# SilverOps — Build Design (final, narrowed)

Date: 2026-08-09. Deadline: hours. Base spec: `silverops-build-spec.md` (Opus). This doc records
the deltas and the build contract; where silent, the Opus spec governs.

## Constraints settled with the user

- No Anthropic API key available → live mode ships as inspectable code, demo runs on replay.
- Runway is hours → strict priority build order; tail features are droppable.
- Deployment: local only for now (replay path must work with zero network).
- Keep: approvals page, report page. Cut: weather pattern (F), no-show prediction (5.6),
  hybrid mode, PDF/DOCX generation.

## Approaches considered

1. **Pure hand-scripted trace, no real agent code** — fastest, but dishonest under judge probing
   and scores nothing on architecture inspection. Rejected.
2. **Live-only with a key acquired later** — blocked on a key that doesn't exist; demo could fail
   live. Rejected.
3. **Real tools + real loop code; recorded run generated by executing the real tools with
   authored reasoning interleaved** — deterministic, offline, honest about what is real
   (tool calls/results) vs authored (model narration in replay). **Chosen.**

## Architecture

- Next.js App Router + TS + Tailwind v4. No chart lib (hand-rolled SVG sparkline). No DB.
- `/types/index.ts` — interfaces exactly as Opus spec §5.
- `/data/*.json` — generated by `scripts/generate-data.ts` (seeded PRNG, committed output).
  Patterns A–E planted; messiness quota (empty languages, null mobility/contacts, inconsistent
  interest tags, near-duplicate names) enforced by `scripts/verify-data.ts` assertions.
- `/lib/agent/tools.ts` — 13 deterministic tool functions per §7.1; pure data ops, no LLM.
- `/lib/agent/loop.ts` + `/app/api/agent/route.ts` — real Anthropic tool-use loop, SSE, active
  only when `ANTHROPIC_API_KEY` is set. `/lib/agent/prompts.ts` — system prompt per §7.3.
- `scripts/record-run.ts` — builds `/data/recorded-run.json`: executes real tools in the demo
  sequence, interleaves authored plan/thinking/judgement events, emits typed `AgentEvent`s with
  relative timestamps (400–900 ms band).
- `/lib/replay.ts` — client-side replay engine streaming recorded events at recorded pace.
- `/lib/store.tsx` — React context + reducer; artifacts (findings, drafts, calendar, contributor,
  report) land here as events arrive; approval status changes persist to localStorage; "Reset
  demo" clears.

## Screens (priority order within UI phase)

1. `/run` — two-pane trace (hero): plan checklist, tool-call cards (args + collapsible result),
   quoted thinking, artifacts materialising right.
2. `/member/[id]` — profile, SVG sparkline w/ visible cliff, cluster links, inferred cause,
   draft w/ approve/edit/decline.
3. `/calendar` — current vs proposed; every change shows rationale; finding-linked chip on the
   mahjong reschedule navigates to cluster members.
4. `/` Morning Brief — attention card, approval count, weekly-pulse win (seeded prior win, not
   Mr Tan), CTA → /run.
5. `/approvals` — queue with approve/edit inline/decline; counts flow back to Brief via store.
6. `/report` — compiled monthly report, print CSS + .md Blob download.
